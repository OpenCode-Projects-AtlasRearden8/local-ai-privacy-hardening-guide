Last updated: 2026-11-05

## What was built

**Local AI Privacy Hardening Guide** — a follow-up manual for people who already run local AI (Ollama, LM Studio, Jan, Open WebUI, etc.), covering privacy hardening in plain English. By Asdale Dynamics, LLC. Distinct from privacy-comfort-handbook (consumer cloud privacy), local-ai-handbook (getting started), and free-privacy-checkup-directory (tools list); this is the *hardening* stage.

### Content (docs/, 9 pages, markdown source of truth)

- `docs/index.md` — who this is for, how to use the manual, education-only disclaimer
- `docs/01-ports-and-firewall.md` — ports local AI opens (11434, 1234, 8080, 8188, 7860...), the `127.0.0.1` vs `0.0.0.0` rule, and firewall commands for ufw/macOS/Windows *plus a plain-English restatement of each rule*
- `docs/02-model-files-and-cache-hygiene.md` — where models live per app, `.safetensors`/`.gguf` vs `.pth`/`.bin` pickle risk, deletion routine, `models-manifest.md` habit
- `docs/03-where-chats-persist-on-disk.md` — data folders per tool, SQLite/JSON/RAG-cache leftovers, verify-delete-by-search method
- `docs/04-autosave-and-screenshot-risks.md` — clipboard managers, OS screenshots, cloud-synced Desktop/Documents, desktop-search indexing, screen-recording hygiene
- `docs/05-shell-history-hygiene.md` — history files per shell, secret patterns in history, targeted `sed`/`tail` trimming that keeps useful lines
- `docs/06-monthly-privacy-reset-ritual.md` — 15-minute monthly ritual in four parts + quarterly extras + habit advice
- `docs/hardening-checklist.md` — printable one-page checklist (23 checkbox items) linking back to each page
- `docs/glossary.md` — plain-English glossary (17 terms)

### Code

- `scripts/build.py` — dependency-light build: renders every `docs/*.md` to `site/*.html` with shared stylesheet, nav, and footer. Uses the `markdown` package when installed, otherwise a built-in fallback renderer (headings, lists, tables, fenced code, task-list checkboxes). Rewrites local `.md` links to `.html` in site output so the same source works on GitHub and as a static site.
- `tests/test.py` — 11 tests: build exit code, all pages built, no stray/stale files in `site/`, valid page structure, all internal `.html` links resolve, no unconverted markdown leakage, checkbox rendering, code-block and table rendering, fallback renderer parity, and a repo-wide secret-pattern scan (`sk-…`, `AKIA…`, `ghp_…`, `PRIVATE KEY`).
- `assets/style.css` — shared stylesheet (warm, readable, mobile-responsive, checkbox styling).
- `site/` — generated output: 9 HTML pages + stylesheet (regenerated by the build; don't hand-edit).
- `README.md` — project overview, repo layout, how to build/run, credits Asdale Dynamics, LLC.
- `LICENSE` — MIT, copyright line exactly: `Copyright (c) 2026 Asdale Dynamics, LLC`.

## How to run it

```bash
python3 scripts/build.py     # build/rebuild the static site into site/
python3 tests/test.py        # run the 11 verification tests
python3 -m unittest discover -s tests -p "test.py"   # same tests via unittest discovery
```

Then open `site/index.html` in a browser (or serve `site/` with any static file server if you prefer absolute-path-free browsing over `file://`).

Python 3.9+ required; no third-party dependencies are mandatory (`markdown` optional, used when present).

## Known gaps / honest limits

- Paths and defaults were written against tool layouts common in 2026; app vendors move folders between releases, so pages emphasize *how to find* the current path rather than freezing exact paths forever.
- The fallback renderer covers the markdown subset used in this repo (headings, lists, tables, fenced code, inline styles, task lists, blockquotes). It is not a general-purpose markdown engine, and the tests pin it to repo content.
- App-specific storage details (e.g., exact Open WebUI SQLite filenames per install method) are stated as "typically" rather than guaranteed.
- No dark mode, no syntax highlighting in code blocks, no search — kept deliberately simple for a small static site.
- Only builds on POSIX-friendly setups out of the box (Windows works for building since everything is Python, but the manual's shell examples are bash/macOS/PowerShell).
- Site is generated; the `site/` folder in this repo reflects the last build (rebuild after editing `docs/` or `assets/`).
